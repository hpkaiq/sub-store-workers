# Agent Note: 复用请求中已校验的分享令牌

Status: implemented

## Problem

上游 Sub-Store 2.44.16 的文件和订阅路由导入 `consumeShareTokenForRequest`。esbuild 优先解析 Workers 覆盖层，构建因此缺少命名导出。Workers 入口已扣减限次令牌。下游再次扣减会提前耗尽令牌，按剩余次数重新查找也会漏掉最后一次请求需要的加密配置。

## Decision

Workers 令牌模块导出请求级消费函数，复用现有的 KV 读写和令牌校验。Workers 入口把已消费的对象传给路由适配层，路由凭证与入口使用同一个值。消费函数按令牌、资源类型和资源名匹配请求中的对象。上游路由可以在最后一次有效请求中继续读取令牌附带的加密配置。

## Alternatives considered

- 仅新增上游要求的命名导出，改动最小。路由依旧拿不到入口已消费的令牌，最后一次请求查不到加密配置。
- 改用上游整个令牌模块，可以减少后续接口差异。Workers 的 KV 更新逻辑需要另外迁移并验证，超出这次接口修复的范围。

## Consequences

路由适配层增加一个内部参数，令牌参数以入口校验通过的值为准。上游 2.44.14 和 2.44.16 均通过 `npm run build`。本地以模拟 KV 调用两版 Worker，验证旧令牌、过期令牌、资源范围和限次令牌，确认文件与订阅在最后一次有效下载时都能解密，且令牌随后失效。
